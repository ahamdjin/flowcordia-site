# Variables and credentials

Use the Environment section in the project sidebar. Variables and Credentials are separate views because ordinary configuration and provider authentication have different lifecycles.

## Variables

Add a named value for the selected environment. Use secret storage for sensitive values. Avoid embedding values in Source files or exported workflow JSON. A variable created in staging should not be assumed to exist in production.

## Credentials

Create a connection for the integration you want to use, then select it in the node configuration. API keys and OAuth connections have different setup requirements. A credential record existing does not prove that the provider has accepted it.

Test with a non-production account first. External actions can send messages, consume API credits or change records. OAuth also requires valid callback configuration and provider permissions.

## References, not plaintext

Workflows should retain credential references, not copy secret values. The local QA pass checked redacted create/list responses, an authorized variable reveal, metadata updates and deletion of synthetic credentials. Live OAuth refresh and rotation remain separate checks.

If a node cannot see a credential, check environment, project permissions, integration type and installed piece version before creating another copy.
